### 2.3 Prompt

**Emplacement** : `BRIEF_ANALYST_SYSTEM_PROMPT` dans `backend/hadara_ai/agents/brief_analyst.py`
**Contenu** : Instructions pour analyser un brief, évaluer sa complétude, identifier les risques, proposer une décision (ACCEPTER/ACCEPTER SOUS RÉSERVE/CLARIFIER/REFUSER)
**Brand** : Injecte `HADARA_DNA` via `get_brand_context_for_prompt()`

### 2.4 Entrée / Sortie

**Entrée** : Brief fields (JSON) + contexte projet + brand context
**Sortie** : `BriefAnalystResult`
```typescript
{
  statut_brief: 'exploitable' | 'exploitable_sous_reserve' | 'incomplet' | 'refuser'
  score_completude: number (0-100)
  complexite_percue: number (1-10)
  decision_recommandee: 'ACCEPTER' | 'ACCEPTER SOUS RÉSERVE' | 'CLARIFIER' | 'REFUSER'
  raison_decision: string
  informations_manquantes: string[]
  questions_client: string[]
  risques: string[]
  niveau_priorite: 'Normal' | 'Urgent'
  brouillon_whatsapp: string
  pricing: { prix_min_fcfa, prix_max_fcfa, heures_min, heures_max, source: 'pricing_engine' }
  contexte_client: { fidélité, nb_projets_precedents, facturation_totale_fcfa, solde_du_fcfa }
}
```

### 2.5 Fallback

Si le provider IA est indisponible → retourne `score_completude: 50` avec `raison_decision: "indisponible"`
Le composant affiche un badge "Fallback" 🟡
